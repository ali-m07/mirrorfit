# Retail image to 3D template prototype

The `/3d/` demo now accepts a front product image and an optional back image. It removes a near-uniform background when the file has no alpha, then bakes the resulting images into the texture atlas of the front and back panels of the existing rigged Softwear garment mesh. The mesh continues to use the existing live pose tracker.

This is a texture-transfer building block inspired by Clothware's garment-template workflow. It does **not** reconstruct new garment geometry from a JPG, estimate a customer's body measurements, or simulate cloth. The rendered fit is limited by the selected template and pose tracking. Product photos should be frontal, centered, with the whole garment visible and a transparent or plain contrasting background. Front and back photos of the same garment provide better coverage.

Implementation: `uvBake.js`, a UV-atlas bake. Instead of a screen-space projection shader, it rasterizes each garment panel's triangles into the destination texture space of the panel's TEXCOORD_0 atlas, producing a plain CanvasTexture per material (FRONT-named materials get the front photo, BACK-named materials the back photo, side panels and trims keep their original texture) that the existing skinned renderer samples unchanged. The UI integration lives in the Softwear checkout under `tools/vendor/softwear` (upstream: TechAngelX/softwear, flattened into this repository — `node_modules/` and `dist/` stay local); rebuild with `npm run build` there. Fit is driven by rig-joint scale matching plus an e2e harness (`tools/e2e/`) that runs the real app against a fake camera and scores placement on pixels — see `output/e2e/fit_log.md`. The served route is `http://127.0.0.1:8000/3d/` from `api_server.py`.

Clothware, Garment3DGen, ReMu, DigiDraper and StyleAI were reviewed as research references. None of their training pipelines or checkpoints are installed in this app. Clothware's demo is not run because it requires separate model assets and has output-directory cleanup behavior. This module uses only the existing rigged mesh and browser rendering.

Verification: webpack production build succeeds. Fit was validated with the headless e2e harness (fake-camera browser run + pixel scoring, `tools/e2e/run_fit_test.py`); the live webcam path still deserves a human check. A camera startup timeout surfaces a visible error instead of an indefinite black loading state.
